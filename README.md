# Mastara Agent News Ranking App

AIエージェントフレームワーク（Mastra）を用いて構築した、ニュースランキングを取得・要約するアプリケーションです。自然言語のリクエストからカテゴリーを判定し、ウェブニュース媒体のアクセスランキング上位3記事を取得して、日本語の要約と出典リンクを返します。

TypeScriptで、Agentの定義、Toolによる外部データ取得、構造化出力による要約、ProcessorによるAgent Loopと回答出力の制御を実装しています。CLIとMastra Studioから同じAgentを実行できます。

## 実装の特徴

- **自然言語によるカテゴリー判定**：LLMが入力の意図を解釈し、対応カテゴリーまたは対象外としてToolへ渡します。
- **取得と要約の連携**：Toolが実行時点の記事を取得し、要約専用Agentが本文を短くまとめます。順位・タイトル・URLは取得値を保持して表示します。
- **Agent Loopの制御**：MastraのProcessorでToolの呼び出しタイミングと回答出力を制御し、重複取得や回答の重複出力を防ぎます。
- **媒体を追加できる構成**：共通インターフェースと媒体固有の取得・解析処理を分離しています。
- **異常系を含む検証**：外部通信不要の26件の自動テストと、実サイト・LLMを使う動作確認スクリプトを用意しています。

## 起動

Node.js 22.18以上、Yarn Classic 1.22.22を使用します。取得したリポジトリのディレクトリへ移動して実行してください。

```sh
cd mastara-agent-news-ranking-app
yarn install --frozen-lockfile
# 初回のみ。既存の .env がある場合はコピー不要
cp -n .env.example .env
# .env の3つのプレースホルダーを下記の設定例に従って編集
yarn dev
```

http://127.0.0.1:4111 のAgentsからニュースランキング用Agent（ID: `news-agent`）を選びます。表示名には選択したウェブニュース媒体の名前が含まれます。停止はCtrl+Cです。同じプロジェクトで開発サーバーを二重起動しないでください。

`.env` の設定例（キーはチャットやGitへ貼らないでください）:

```dotenv
OPENAI_API_KEY=自分のAPIキー
MASTRA_MODEL=openai/gpt-4o-mini
NEWS_PROVIDER=livedoor
```

`.env.example` の `YOUR_..._HERE` は入力用の目印です。コピー後はAPIキー、モデル名、ウェブニュース媒体の3項目を実際の値へ置き換えてください。`NEWS_PROVIDER` は未設定なら `livedoor` ですが、プレースホルダーや空文字のままではエラーになります。

CLIからも実行できます。開発サーバーの起動は不要です。引数を省略すると「人気の記事を教えて」を実行します。

```sh
yarn agent '人気の記事を教えて'
yarn agent 'エンタメの人気の記事を教えて'
yarn agent 'スポーツの人気の記事を教えて'
```

## 対応する質問

現在の媒体モジュールでは、次の9カテゴリーに対応しています。対応カテゴリーや言い換えは媒体ごとの定義で管理します。

| カテゴリー | 入力例・言い換え               |
| ---------- | ------------------------------ |
| 総合       | 総合・指定なし                 |
| 国内       | 国内・日本国内                 |
| 政治       | 政治・政界                     |
| 海外       | 海外・国際・世界               |
| 経済       | 経済・ビジネス・金融           |
| IT         | IT・ＩＴ・テクノロジー・テック |
| スポーツ   | スポーツ                       |
| 芸能       | 芸能・エンタメ・芸能界         |
| 女子       | 女子・女性向け・女子向け       |

「人気の記事を教えて」は総合、「国際ニュースのランキングを教えて」は海外、「女性向けの人気記事を教えて」は女子を取得します。「政治」などカテゴリー名だけでも質問できます。毎回の入力からカテゴリーを判定します。

対象は上記の9カテゴリーです。対応表にないカテゴリー（例：科学・地域）、天気や雑談などの対象外質問、複数カテゴリーの同時依頼は案内して終了します。会話の永続化は行いません。

回答はカテゴリー、取得日時（日本時間）、ランキングリンク、各記事の順位・タイトル・短い要約・本文リンクです。「最新の記事順」ではなく、取得時点のアクセスランキングです。

## AIエージェントの処理と役割

MastraはAgent・Toolの登録と実行、LLMへのリクエスト、Toolの実行結果を受け取って応答を続けるAgent Loopを担当します。カテゴリー判定と要約はLLM、HTTP取得・HTML解析・表示文の組み立てはアプリケーション側の処理が担当します。

1. LLMが質問を対応カテゴリー・対象外のいずれかに分類し、newsToolを呼びます。
2. Toolが入力スキーマを検証します。対象外ならニュースサイトへ通信せず案内文を返します。
3. 対応する場合はランキングHTMLから1〜3位を取り出し、概要ページ内の本文リンクをたどって本文だけを抽出します。
4. Tool内で要約専用のLLMを呼び、本文の短い要約だけを構造化データで取得します。
5. タイトル・順位・URL・取得日時はプログラムが取得値から組み立てます。出力Processorにより、CLIとStudioのどちらでもこの表示文を返します。

Processorが最初のステップでToolを必ず呼ぶように設定し、次のステップではToolを無効にします。外側のAgent Loopは「分類とTool実行」「完了」の2ステップです。Tool内の要約用LLM呼び出しを含め、成功時のモデル呼び出しは通常3回です。対象外では要約用LLMは呼びません。対象カテゴリーの意味解釈はLLMが担当するため、未知の表現の分類が常に正しい保証はありません。取得先カテゴリーはプログラムの固定一覧で制限します。

本文は外部のデータとして扱い、本文中の指示に従わないようAgentに指示しています。記事本文にない内容を推測せず、報道上の疑いや主張を断定に変えない方針です。

## 取得失敗の扱い

- ランキング取得・解析に失敗: エラーメッセージを返し、記事を生成しません。
- 1記事だけ失敗: その順位とリンクを維持し「記事本文を取得できませんでした」と表示します。4位を3位へ繰り上げません。
- 要約生成に失敗: 順位・タイトル・リンクを維持し「要約を生成できませんでした」と表示します。
- 本文が12,000文字を超える、または公開本文の別レイアウトの場合: 取得範囲を明示した要約にします。
- 各HTTPリクエストは15秒、HTMLは2MBを上限にし、記事は順番に取得します。
- 取得先は媒体モジュールで許可したHTTPSのホスト・パスに限定し、同じ許可範囲内のリダイレクトのみ3回まで追跡します。
- キャッシュは設けず、質問ごとに取得します。サイト変更やアクセス制限で取得できなくなる場合があります。

## ファイル構成

```text
.
├── .env.example                           # 設定値のテンプレート
├── scripts/
│   ├── ask.ts                             # yarn agentのCLI入口
│   ├── check-news.ts                      # 実サイトの全9カテゴリーを確認
│   └── check-agent.ts                     # 実LLMを含めた動作確認
├── src/
│   ├── mastra/
│   │   ├── index.ts                       # Agent登録・サーバー設定
│   │   ├── agents/
│   │   │   ├── news-agent.ts              # 入力の分類とTool呼び出し
│   │   │   └── news-summarizer.ts         # 記事本文の要約専用LLM
│   │   ├── tools/
│   │   │   └── news-tool.ts               # 取得・要約・表示をつなぐ
│   │   └── processors/
│   │       ├── ranking-flow.ts            # Agent Loopの制御
│   │       └── fixed-presentation.ts      # 取得値を保った回答を一度だけ出力
│   └── news/
│       ├── types.ts                       # 記事・ランキング・媒体の共通型
│       ├── categories.ts                  # 選択媒体のカテゴリーと案内文
│       ├── ranking-service.ts             # 取得を依頼し媒体名を付加
│       ├── format-ranking.ts              # LLMを使わず表示文を組み立て
│       └── providers/
│           ├── index.ts                   # NEWS_PROVIDERの検証・媒体の選択
│           └── livedoor.ts                # URL・HTTP取得・HTML解析
└── tests/
    ├── news.test.ts                       # 順位保持・本文抽出・取得先制限
    ├── providers.test.ts                  # 媒体選択・媒体共通の表示
    ├── http.test.ts                       # HTTP異常応答・上限・中止
    ├── failures.test.ts                   # 解析失敗・本文リンク・失敗時の表示
    └── processors.test.ts                 # 出力制御・リクエスト分離・Loop制御
```

`yarn agent` は `scripts/ask.ts` から登録済みAgentを直接呼びます。`yarn dev` はMastra付属のStudioを起動し、ブラウザから同じAgentを呼びます。`src/mastra` はバックエンドの定義であり、Studioの画面実装ではありません。`scripts`、`news` 配下の名前や構成はこのアプリ独自です。

`NEWS_PROVIDER` は省略時も `livedoor` です。未対応の値は起動時にエラーになります。URLは媒体固有のHTML構造・取得先制限と一緒に `src/news/providers/` 配下の媒体モジュールで管理します。別媒体を追加するときは `NewsProvider` を実装するモジュールを作成し、`providers/index.ts` に登録したうえで `.env` を変更します。URLだけを変えて別媒体を利用することはできません。現在利用できる媒体識別子は `livedoor` のみです。

## 検証・整形

| コマンド            | 内容                                        | 外部通信・API利用                     |
| ------------------- | ------------------------------------------- | ------------------------------------- |
| `yarn test`         | 5ファイル・26件の自動テスト                 | なし                                  |
| `yarn typecheck`    | アプリ・スクリプト・テストの型検査          | なし                                  |
| `yarn lint`         | ESLintによるコード検査                      | なし                                  |
| `yarn format:check` | Prettierによる整形チェック                  | なし                                  |
| `yarn lint:fix`     | ESLintで修正できる問題を修正                | なし                                  |
| `yarn format`       | Prettierで整形                              | なし                                  |
| `yarn check:news`   | 全9カテゴリーの上位27記事を取得・検証       | ニュースサイトへの通信                |
| `yarn check:agent`  | 9カテゴリー＋対象外3パターンを実Agentで検証 | ニュースサイト・LLM API（料金が発生） |

通常の変更確認は次のコマンドで行います。

```sh
yarn test
yarn typecheck
yarn lint
yarn format:check
```

自動テストは、順位保持、本文抽出、URL制限、ランキングや記事本文の取得失敗、要約がない場合の表示を検証します。HTTPの異常応答、リダイレクト上限、2MBの受信上限、中止の伝達、本文12,000文字の境界も対象です。Processorについては、回答を一度だけ出すこと、別リクエストと回答を混ぜないこと、最初のステップだけToolを呼ぶことを確認します。

実サイトとLLMを含む確認は、`.env` を設定してから必要に応じて実行します。開発サーバーは不要です。

```sh
yarn check:news
yarn check:agent
# カテゴリーの内部キーで対象を絞る例（総合・芸能・対象外3パターン）
yarn check:agent general entertainment unsupported
```

`check:agent` はカテゴリー判定、上位3件の取得、回答中のタイトル・リンク・取得日時、対象外の案内、外側のAgent Loopが2ステップであることを検証します。要約の事実関係や日本語の品質を自動評価するものではありません。実サイト／LLMの確認結果は外部サービスの状態に依存します。

VS Codeは保存時にPrettier整形とESLint修正を実行します。設定は `.vscode/`、`.eslintrc.json`、`.prettierrc` で管理しています。ESLintは8.57.1、TypeScriptは5.9.3を使用しています。

## ビルド

開発サーバーを停止してから実行します。

```sh
yarn build
node --env-file=.env .mastra/output/index.mjs
```

`yarn build` は `.mastra/output` に成果物を生成し、サーバーは起動しません。上記の `node` コマンドで成果物を起動します。本番では `.mastra/output` をNode.js環境へ配置し、APIキー・モデル・媒体の環境変数を実行環境で設定します。現在の実装はローカルでの実行・検証を対象としており、本番公開向けの認証・永続化DBは未実装です。現在の待受先は127.0.0.1:4111です。
